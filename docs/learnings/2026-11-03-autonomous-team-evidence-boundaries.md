# 自律チームの検証を、権限境界と同じコードの証跡に結び付ける

- 日付: 2026-11-03
- 領域: agents-setup / autonomous-team
- 種別: design-tradeoff

## 問題

独立した worktree で実装し、テストとレビューを通してから完了させたい。しかし、フックからの実行、未コミット変更の統合、レビュー中の変更を区別しなければ、検証したつもりでも別の内容を完了扱いにしてしまう。

## 試して駄目だった道

- Stop フックから受け入れコマンドを実行する設計は却下した。フックのプロセスは通常の Bash ツールのサンドボックス境界の外で動く。
- レビューを記録した時点だけのハッシュでは、レビュアーが読んだ内容を特定できない。レビュー開始前のハッシュが必要だった。
- 担当外の変更だけを保護しても、担当ファイルに既存の変更があると、コミット済み状態から始めたワーカーの成果物で上書きしてしまう。
- 任意のタスク ID を Claude の Stop フックに使うと、実際の `session_id` と一致せず、検証が発火しない。

## 効いたアプローチ

受け入れコマンドはリーダーの Bash ツールから実行する。フックは保存済み証跡と現在の内容の照合に限定する。テスト後に取得したスナップショットをレビュアーへ渡し、レビュー本文の `Snapshot: HASH` と記録時の現在値を照合する。

開始時点で担当ファイルが変更済みなら拒否し、担当外の既存変更は内容と Git 状態を保護する。Claude では実際の会話 ID を使い、会話ごとに1タスクを扱う。状態は Git メタデータ内に会話と checkout の両方で分離する。

フックの Git 照会も、fsmonitor、外部 diff、textconv、フック、設定済み filter の外部コマンドを無効にして実行する。Git の無視対象ファイルや実行環境まではハッシュの対象にしない。

## なぜ効いたか

検証を実行する権限境界と、どの内容を検証したかの境界を別々に固定できるためである。フック内の照合が失敗しても、コマンドを再実行して権限境界を越えない。根拠: 10件の回帰テストが通過し、Git の外部コマンドに設定したマーカー生成がフック経由では実行されないことを確認した。

## 一般化できる原則

- worktree の成果物を統合する前に、基準コミットと統合先の未コミット変更を確認する。
- テストとレビューの証跡には、確認開始前の対象ハッシュを含める。
- フックが実行するツールも、そのツールが読み込む外部実行設定まで点検する。
