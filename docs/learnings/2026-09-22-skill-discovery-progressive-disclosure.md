# スキル最適化は選択条件と実行手順の保存を分けて検証する

- 日付: 2026-09-22
- 領域: agents-setup / shared skills
- 種別: design-tradeoff

## 問題

共有スキル95件をMacへ復元したところ、Codexの一覧では説明文の末尾が省略され、コード調査全般をGraphifyへ誘導する定義や、文書作成を長い質問手順へ誘導する定義が残っていた。Claude専用の運用や、旧マシンにしかないCLIも共有の前提になっていた。

## 比較して却下した候補

- 未導入ツールに依存するスキルを一括削除・無効化する案: 他のハーネスや将来の環境で使う用途まで失うため、選択条件と実行前確認の修正を選んだ。
- 長いGraphifyビルド手順を短い文章と再構成したコードで置換する案: uvの隔離環境からPythonを再解決する処理やキャッシュ整合の手順が欠けるため、既存の実行コードを用途別参照へ移す方針に修正した。
- 共通バリデータのエラーをすべて削除で解消する案: Claude用の呼び出し制御や外部アプリ管理のメタデータも対象になるため、変更前後を比較し既存の互換性差分と新たな不具合を分けた。

## 効いたアプローチ

1. 保存元とシンボリックリンクを確認し、リポジトリ内の正本だけを編集する。
2. 説明文の先頭に用途を置き、一般的な依頼まで巻き込む発動条件を絞る。
3. 入口には共通の判断と参照先を残す。ビルド、編集、デザインなどの詳細は、その操作を行う時だけ読む。
4. 手元のツールの有無を確認し、未導入を明示して利用可能な代替へ進む。スキルの存在を、ツールや認証の存在と取り違えない。
5. 独立レビューで代表的な依頼を通し、過剰な質問・別ハーネスへの誘導・実在しないスクリプト呼び出しを確認する。

## なぜ効いたか

選択時の説明文、選択後の入口、必要時の詳細を別々に扱うことで、技術的な知識を捨てずに不要な指示の読み込みを減らせる。実行コードの保存と実行可能性の確認は、文章量の削減率からは判断できない。

裏づけ: 95件のYAMLと名前を検証し、リンク先の存在とlive側との内容一致を確認。独立レビューで見つけたPDFフォームの拡張子欠落を修正した。CLI未導入の機能について実動作成功とは扱わない。

## 一般化できる原則

- スキルの説明文は、途中で省略されても用途を識別できる順序にする。
- 実行手順を参照へ移す変更では、コード・パス・前提・出力の不変条件を保存していることを確認する。
- 共通ストアの監査では、構文、ハーネス固有メタデータ、ホスト依存機能の3種類を区別する。
