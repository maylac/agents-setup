# 指示ファイルのリンクとClaudeの自動読込を区別する

- 日付: 2026-09-26
- 領域: agents-setup / Claudeの指示書読込規則
- 種別: design-tradeoff

## 問題

共通の `~/CLAUDE.md` は `home/AGENTS.md` へのリンクで、Claude用の `~/.claude/CLAUDE.md` は生成コピーだった。これらが正しく解決することだけでは、各プロジェクトの `AGENTS.md` がClaudeの文脈へ自動読込された証拠にならない。

公式の読込規則では、直接の `AGENTS.md` 対応はClaude Code v2.1.277以降。祖先に `CLAUDE.md` または `CLAUDE.local.md` がある場合、既定ではプロジェクトの `AGENTS.md` が読み込まれない。両方読むには設定が必要と説明されている: [Claude Code memory](https://code.claude.com/docs/en/memory)。

このシェルではClaude CLIを実行できず、実際のClaude実行時の読込状態は未検証。したがって、再現済みの問題として扱わず、指示の所在と読込条件を確認する必要があった。

## 比較して却下した候補

- リンクが解決するので全ての `AGENTS.md` が読込済みとみなす案: ファイルの所在とClaudeの探索優先順位を混同する。
- リンクを削除・移行したり、未確認の実行時設定を新設したりする案: 正本と生成経路を越える変更で、CLIもなく効果を検証できない。

## 効いたアプローチ

1. `~/CLAUDE.md` が正本の `home/AGENTS.md` を指すことを確認する。
2. `~/.claude/CLAUDE.md` の生成元を編集し、同期スクリプトで生成物を更新する。生成経路とリンク構成を保つ。
3. Claude Codeがプロジェクトの `AGENTS.md` を読込済みか不明なら、対象プロジェクトの指示書を明示的に読む。

## なぜ効いたか

正本と生成物の所有関係を保ったまま、Claudeの既定探索で抜けるプロジェクト指示を明示読込で補える。同期チェックはリンクと生成コピーを検査するが、Claudeの実行時文脈までは証明しない。

裏づけ: 指示更新前の `bash scripts/sync-instructions.sh --check` は成功し、各リンクの解決先も確認した。このシェルではClaude CLIを実行できず、実行時動作は未検証。今回の監査・修正範囲は[指示書監査](../agent-instructions-audit-2026-09-26.md)を参照。

## 一般化できる原則

- 指示ファイルのリンクが有効でも、ハーネスがそのファイルを自動読込したとは限らない。
- 自動読込を確認できない時は、実行時設定を推測で変更せず、適用対象の指示書を明示的に読む。
