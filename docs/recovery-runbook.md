# 再起動後の復旧判断

この手順は、遠隔操作する Mac が再起動後に応答しないとき、次のどちらを優先するか判断するためのものです。

- 物理アクセス時の保護を下げて、自動ログインを使う。
- FileVault を維持し、LAN 上の別端末から起動前に解除する。

## 選択肢 A：FileVault を無効にして自動ログインする

FileVault が有効な間、自動ログインは使えません。
FileVault を無効にしたうえで自動ログインを設定すると、再起動後にユーザーのデスクトップまで進む構成にできます。

この構成では、物理的に Mac を操作できる人が再起動するだけで、そのユーザーにアクセスできます。
機密データを扱う Mac や、持ち出し・盗難の可能性がある Mac には選びません。
FileVault を無効にする前に、物理的な設置場所とアクセス管理を確認してください。

自動ログインの設定だけでは、起動後のネットワーク接続や遠隔操作経路、ユーザーごとの LaunchAgent の実行までは確認できません。
対象の Mac で再起動後の GUI ログインと必要な処理を実際に確認できた場合に限り、この経路を復旧策として扱います。

## 選択肢 B：FileVault を維持して SSH で起動前に解除する

Apple silicon 搭載 Mac と macOS 26 以降では、再起動後、Remote Login が有効でネットワーク接続があれば、SSH 経由で FileVault を解除できます。
解除操作には、別にオンラインの LAN 端末、対象 Mac まで届くローカルネットワーク経路、利用可能な SSH 認証情報が必要です。

この機能は FileVault の解除を可能にします。
**SSH 接続または FileVault 解除だけで、GUI ユーザーセッションの開始や LaunchAgent の実行が確認できるわけではありません。**
実際に GUI ログインが完了したか、対象の LaunchAgent が動いたかは、ログイン後の画面や個別の稼働確認で判定します。
自動ログインが未確認なら、起動前 SSH の成功を「遠隔復旧完了」と扱いません。

### 実行前の確認

次の条件をすべて事前に確認できる場合に、この経路を選びます。

1. 対象 Mac が Apple silicon 搭載で、macOS 26 以降である。
2. 再起動前から Remote Login が有効である。
3. 再起動後、ログイン前の Mac が使える LAN 経路につながる。別端末もオンラインで、その経路から対象 Mac に到達できる。
4. SSH の認証情報を安全に利用でき、対象 Mac で FileVault 解除まで動作することを事前に確認している。

単に SSH の宛先や中継経路が見えるだけでは、Mac が起動したこと、FileVault が解除されたこと、GUI セッションが始まったことの証拠になりません。
各段階を別々に確認してください。

### 安全策とフォールバック

SSH は信頼できるローカルネットワーク内だけで使い、インターネットへの公開やルーターのポート転送は設定しません。
別端末と SSH 認証情報は対象 Mac と分けて保管し、認証情報をログや共有メモに残しません。
FileVault の復旧キーも安全な別経路で保管します。

条件が一つでも満たせない、または解除後の GUI ログインを確認できない場合は、遠隔復旧が成功したと推測せず、現地で画面を確認して通常のログインを行います。
必要なら Apple の復旧手順に従い、保管済みの復旧キーを使います。
