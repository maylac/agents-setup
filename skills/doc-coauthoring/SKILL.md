# Collaborative Document Development

Use this process when the user wants to develop a substantial document together. For a request to produce a complete draft from supplied material, draft it directly and use only the relevant checks below. Match the requested pace; the user may skip stages or edit the document themselves.

## Gather the context that changes the document

Establish the audience, purpose, source material, destination, and any required template from the request and accessible files. Read supplied documents or connected sources through the available tools. Ask only about gaps that would materially change the result; do not repeat questions already answered in the conversation.

Keep an explicit distinction between supplied facts, supported findings, and assumptions. If a source is unavailable, state the narrow limitation and proceed with the useful material at hand. Do not ask for broad account access when the needed evidence is already available.

## Draft and refine

1. Use the supplied structure, or choose one suited to the reader's decision or task. Start with the substantive proposal or explanation; write its summary after the argument is stable.
2. Produce a concrete draft or section for feedback. Brainstorm alternatives when the direction is unresolved or the user asks; do not require numbered option selection before every section.
3. Apply feedback in place with the host's available edit tools. Preserve the user's edits, formatting constraints, and intended meaning. Carry stated preferences into later sections.
4. Read the complete document for contradictions, repetition, missing transitions, unsupported claims, and assumed reader knowledge. Fix the specific problems found.

For Japanese explanatory narrative, use [cognitive-rhythm-writing](../cognitive-rhythm-writing/SKILL.md) when shaping prose rhythm; for technical Japanese, use [japanese-tech-writing](../japanese-tech-writing/SKILL.md). Read relevant guidance once, then reuse it through the task. Choose the artifact-format skill when producing Word, slides, or another format.

## Test it as a reader

Reader testing is useful for substantial specs, decision documents, and unfamiliar audiences. Select the questions the intended reader must be able to answer, such as the proposed decision, its evidence, its tradeoffs, and the next action.

If independent agents are available and authorized, give a reviewer only the draft, intended audience, and those questions. Ask it to identify answers supported by the document and concrete ambiguities. A single focused review is usually enough; repeat only after material changes or unresolved findings. Use the configured runtime and model rather than requiring a particular provider.

If no independent reviewer is available, perform a separate reader pass and state that it was a self-review. A manual fresh-session review is an option when the user wants it, not a prerequisite for delivery.

Resolve demonstrated gaps without expanding the assignment. Do not invent reader-test results or iterate until an arbitrary score or question count is reached.

## Deliver

Provide the document or its file link, summarize material changes, and identify unresolved factual inputs. Finish when the requested draft or revision is ready; do not add another approval round merely to declare completion. External publication or sending follows the user's actual authorization.
